Load Balancer Simulator

What is this simulator?

This simulator shows how a load balancer spreads traffic across backend servers in a dynamic network environment. Its purpose is to showcase the load balancer software I built and how it responds to changing network environments and balancing configurations. The simulator creates mock clients and backends alongside real HTTP requests that get sent to an actual instance of the load balancer which determines the request routing and returns the responses back to the client.

Scenarios:

Each scenario models a different operating condition, such as stable traffic, overloaded backends, partial failures, or network partitions. These presets make it easier to see how the balancer reacts to different real-world events.

Balancing strategies:
  • - Round Robin: rotate traffic evently to each backend.
  • - Weighted Round Robin: backends can be marked with integer weights with heavier backends being given more traffic. This strategy can be useful when the backend machines are of varying power or capacity.
  • - Least Connections: sends traffic to the least-busy server. This strategy can be useful when request processing time is variable, where regular round robin can end up with hot-servers.
Technical details:

The load balancer itself is a real HTTP routing component that receives client requests, evaluates the active backend pool, and applies a selection strategy such as round robin, weighted round robin, or least connections. It tracks backend health, active connections, request rate, and observed latency so it can adapt traffic distribution during failures or degraded conditions.
